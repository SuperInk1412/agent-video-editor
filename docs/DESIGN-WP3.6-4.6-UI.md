## 2. A · WP3.6 代码图层界面

### 2.1 检查器分区「代码图层」

`code` 元素选中时，在现有分区之后注册一个分区（`registerInspectorSection({ id: 'code', order: 40, when })`）：

```
▾ 代码图层
  源      rain · p5 1.9.4        [查看源码]
  参数
   密度     0.50   ◆
   颜色     █ #ff8800  ◆
   速度     1.00
  渲染     实时 · 12.4 ms/帧 · 缓存命中 96%
```

- 源行：`manifest.label`（没有就用 id）+ runtime 徽标（`--font-mono`、10px）+ `查看源码` 文字按钮。
- 参数行沿用现有属性行（28px 高、`tabular-nums`、可打帧的带 ◆）；控件按 manifest `type`：`number`→数字输入（有 `range` 时带滑杆）、`color`→色块+输入、`boolean`→开关、`enum`→下拉。
- 参数写入走 `codeParamSet`（可打帧的走 `keySet`，与现有关键帧语义一致）；**一次拖动 = 一次撤销**（用现有 `op()` 的合并/事务规则）。
- 渲染行：`实时`（live）/ `烘焙`（bake，只读缓存）/ `等待首帧`（`--warn`）/ `上一帧`（fallback，`--text-3`）；显示最近一帧耗时与缓存命中率（来自 `preview.meshStats`/raster 状态；没有就显示 `—`）。
- 源检查失败时（`vdm source check` 的契约失败），分区顶部一行 `--danger`：`这个源没通过检查：读取了系统时钟`，`查看详情` 打开源码视图的检查结果页。

### 2.2 源码视图（`source-view.js`）

- 入口：检查器的 `查看源码`；命令面板 `查看源码`（选中 code 元素时可用）。
- 形态：覆盖工作区的模态（`--scrim` + `--surface-2`，`min(1100px, 88vw) × min(720px, 80vh)`），**只读**：
  - 顶部：源名 · runtime · `manifest.json` 版本；右侧 `在编辑器中打开`（调系统默认程序）、`重新检查`、`关闭`（Esc）。
  - 左侧文件列表（`manifest.entry` + `files` 的键），右侧 `<pre>` 代码（行号、`--font-mono`、只读、可选中复制）。不做语法高亮（零依赖，保持简单；以后可加）。
  - 底部状态条：文件大小、哈希前 8 位、上次检查时间与结果。
- 错误态：源文件缺失 → 一行 `--danger`「找不到 main.js」+ `重新扫描`；manifest 无效 → 显示解析错误原文。

### 2.3 渲染状态与错误

- 视口里该元素的左上角（屏幕坐标，跟随元素）在 `等待首帧` 时显示 12×12 的 `--warn` 圆点 + 悬停「等待代码图层的首帧」；`fallback` 时显示 `--text-3` 方块 + 悬停「正在显示上一帧」。
- 这些标记只在**编辑视口**显示，播放/导出不画；不影响像素对拍（探针在暂停态读）。

### 2.4 验收（Electron 探针 `scripts/check-code-ui.mjs`）

1. 选中 code 元素 → 分区出现，参数行数量 = manifest 参数数；`◆` 只出现在 `keyable` 参数上。
2. 改一个参数 → `project.vdm.json` 的值变化、rev +1、`Ctrl+Z` 回退。
3. 对 `keyable` 参数点 ◆ → 关键帧写入；时间线出现菱形。
4. `查看源码` → 模态打开、`<pre>` 文本等于源文件、Esc 关闭。
5. 坏源（读取系统时钟的 fixture）→ 分区出现 `--danger` 行与 `查看详情`。
6. 等待态/fallback 标记：把 `/api/raster` 指向 500 → 标记出现；恢复后消失。
7. 现有探针（`check-review-ui`、`check-timeline-marks`、`check-code-layer-preview`）仍 PASS；CSS 颜色 grep 为空。

## 3. B · WP4.6 源编辑界面

### 3.1 来源标记

- 检查器头部：元素名后一个小徽标 `源 · title-card`（`--source` 色，10px，`data-tip` 显示源 id 与节点 id）。
- 时间线行：名称前一个 12×12 的源图标（`i-source`），仅当 `el.source` 存在；**不改行高、不改按钮顺序**（放在锁图标之后、类型点之前，悬停才显示完整提示）。
- 大纲（左栏图层）同样加图标。

### 3.2 叠加 / 接管（逐属性）

- 对 `el.source` 元素的每个来自源的属性行，属性名右侧加一个 20px 的分段开关：`叠加` / `接管`（当前态高亮 `--source`，另一态 `--text-3`）。
  - `叠加`（默认）：显示源值 + 本地覆盖（`el.sourceMode[path] = 'overlay'`）。
  - `接管`：本地值完全覆盖源（`'takeover'`）；源更新不再改这个属性。
- 开关只对「源里有这个属性」的行出现；其余行保持现状。
- 点击一次 = 一次撤销；切换后该行的值预览立即更新（走 `op()`）。
- 属性链接/父子关系行不显示该开关（本期不做）。

### 3.3 冲突模态

- 触发：`POST /api/sources/<id>/merge` 返回 `conflicts[]` 非空时（例如源重新编译后与人改过的属性冲突）。
- 形态：`--scrim` + `--surface-3` 卡片（宽 `min(900px, 80vw)`），标题「源更新后有 2 处冲突」：
  - 每条一行：`title-card / h1.text`，下面三列：`源（新）`、`你的修改`、`合并后`（默认取你的修改，可点列头切换）。
  - 行尾：`保留我的` / `用源的`（单选）；底部 `全部用源的` / `全部保留我的`。
  - `应用`（primary）→ 一次事务写入所有选择；`取消` 不改。
- 冲突解决后写入 `base.json` 的合并记录（由 4.4 定义），报告里不出现"已自动合并"的假话。

### 3.4 脱离源码

- 入口：元素右键菜单 / 检查器 ⋯ 菜单 → `脱离源码`（`--danger` 文字，需确认）。
- 行为：删掉 `el.source` 与 `sourceMode`，元素保留当前求值后的属性值（一帧的值写成本地值），**一次撤销**可回到有源状态。
- 确认文案：`脱离后这个元素不再跟随源更新；当前画面会保留。`

### 3.5 验收（Electron 探针 `scripts/check-source-ui.mjs`）

1. 用 `html-title-card` 夹具编译出的元素 → 检查器有 `源 · …` 徽标、时间线行有源图标。
2. 切一个属性到 `接管` → 该属性写 `takeover`、源更新不再改它；`Ctrl+Z` 回 `overlay`。
3. 制造 2 条冲突 → 模态出现、默认保留我的、`应用` 后值符合选择、撤销一步回退。
4. `脱离源码` → `el.source` 消失、值保留、撤销恢复。
5. 没有源的元素不出现任何新控件；CSS 颜色 grep 为空；现有探针全 PASS。

## 4. 需要后端提供的接缝（由 4.1/4.2/4.4 落地，本方案只列形状）

| 接口 | 用途 |
|---|---|
| `GET /api/sources` / `GET /api/sources/<id>` | 源列表、manifest、文件正文（源码视图） |
| `POST /api/sources/<id>/check` | 运行 `vdm source check`（契约失败原因） |
| `POST /api/sources/<id>/writeBack` | 写回源（`{ nodeId, path, value } → { ok } \| { fallback, reason }`） |
| `POST /api/sources/<id>/merge` | `{ base, ours, theirs } → { result, conflicts[] }` |
| `POST /api/ops` 现有 op | `sourceMode` 切换、脱离源码用新 op（`sourceDetach`），仍走 `core/ops.js` |

## 6. 需要你拍板的几点

1. **源码视图只读**（不做编辑器）——可以吗？还是至少要在里面改 `manifest.json` 的参数默认值？
2. **叠加/接管开关放在属性名右侧**，还是做成属性行右键菜单（更省空间但更难发现）？
3. **冲突模态默认「保留我的」**——对吗？（另一种默认是「用源的」，更符合"源是权威"，但会盖掉人的修改。）
4. **脱离源码放在右键菜单 + 检查器 ⋯ 菜单**，需要二次确认——够不够显眼？

## 7. 修订 R1（2026-10-30，用户拍板）

四个问题都选 **A**，但每一条都有重要修正；与前文冲突时以本节为准。

### 7.1 源码：只读，但「刷新」=「载入外部修改」

- 不做代码编辑器；窗口里给 `在编辑器中打开`、`让 AI 改`（把意图填进 AI 页输入框）两个按钮。
- **外部修改的载入必须走事务**：外部编辑器改的是 `sources/<id>/` 副本，工程里的源码才是真值。所以按钮不叫「刷新」而叫 **`载入外部修改`**：
  1. 对比副本与 `project.sources[]` 里的正文，显示**改了哪些行**（+/- 行号）；
  2. 自动跑契约检查（`vdm source check` 同款）；
  3. 通过后一次 `sourceWrite` 写入（进撤销历史、来源 `外部编辑器`）；不通过则列出原因，不写。
- **文件监视**：`sources/<id>/` 变化时给一条不打扰的提示 `源码已在外部修改 [载入]`（不是模态）。
- **不在源码窗口里改 manifest 默认值**（会影响所有用这份源的元素）。默认值改法：参数行右键菜单 **`把当前值设为默认`**（一次可撤销的 `sourceWrite`）。

### 7.2 叠加/接管：只出现在源真正驱动的属性上

- 开关放属性名右侧，但**只有源给出了值或动画的属性**才显示；其余行不出现。
- 用两个小图标区分状态（叠加 / 接管），悬停写清效果；**比例属性（透明度、缩放）的「叠加」是相乘**（§7.3），tooltip 要写明。
- 用户第一次改源驱动的属性时**默认进入叠加**，不需要先选模式。
- 检查器 `⋯` 菜单加 **`全部叠加` / `全部接管`**（整个元素）；右键菜单也放一份作为第二入口。

### 7.3 冲突：不弹窗，进审阅页统一处理

- **不另做冲突模态**。冲突就是 `needs-decision` 的变更集，在 WP2.5 的审阅页里处理，可以直接用「在画面里预览」看效果。
- 默认**保留我的**；关掉不处理 = 保留我的，记录留在审阅页待决定，不卡住工作。
- 冲突行显示这次源更新的 **intent**（变更集里已有），帮用户判断"AI 这次想改什么"。
- 提供 `全部保留我的` / `全部用源的` 批量按钮。

### 7.4 脱离源码：不做确认框，做撤销提示

- 两个入口（右键菜单 + 检查器 `⋯`）保留；直接执行，弹一条带按钮的提示 `已脱离源码，当前画面已保留 [撤销]`（不做二次确认）。
- 支持**多选**一次脱离多个元素；`⋯` 菜单加 **`脱离整个源`**（这份源码生成的全部元素）。
- 来源徽标的悬停提示写明：`脱离后不再跟随源码更新，只能用撤销恢复`（没有"重新关联"）。

### 7.5 对估时与拆分的影响

- 3.6a：检查器分区 + 参数控件 + 渲染状态（1 天，不变）
- 3.6b：源码视图 + 载入外部修改（diff/契约检查/事务）+ 文件监视 + `让 AI 改`（1.5 天，+0.5）
- 4.6a：来源标记 + 只在源驱动属性上的叠加/接管 + `全部叠加/接管`（1 天，不变）
- 4.6b：审阅页的冲突处理（含 intent 与批量按钮）+ 脱离（多选 / 整个源 / 撤销提示）（1.5 天，不变）
- 4.6b 依赖 WP4.4 的 `merge` 接口；3.6 可以立即开工。
