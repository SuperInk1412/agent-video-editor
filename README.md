# VedioMaker

**自己定义编辑 · 实时预览 · AI 辅助 · Blender 出片**

VedioMaker 是一个本地的视频作曲台：时间线由你自己定义，画面在浏览器里即时预览，
最终画面交给 Blender 渲染，而 AI（DSH-TUI agent）和你操作的是**同一份项目文件**——
所以你随时能看见它在改什么、打断它、或者自己接手。

```
┌─────────────────────────────────────────────────────────────┐
│  Electron 窗口 (或浏览器打开 localhost)                       │
│  ┌──────────┬─────────────────────┬───────────────────────┐  │
│  │   媒体   │  WebGL2 实时预览     │ 检查器 / AI / 流水线   │  │
│  └──────────┴─────────────────────┴───────────────────────┘  │
│                    时间线（相机 + 元素 + 关键帧）              │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP (127.0.0.1:random)
┌───────────────────────────┴─────────────────────────────────┐
│ Node 引擎：项目文件读写 · 媒体探测 · 渲染队列 · 截图 · SSE     │
│   ├── Blender 5.x 无头渲染 (bpy：图层 + 合成器 + ffmpeg 封装) │
│   └── dsh --profile headless --json  (AI 编辑代理，可打断)     │
└──────────────────────────────────────────────────────────────┘
```

## 快速开始

```bash
# 在仓库根启动：先弹项目选择器（不再默认死开 demo）
npm start

# 在项目目录里启动就直接打开那个项目（npm start 的 cwd 是包根，脚本读 INIT_CWD）
cd projects/nightcity && npm start

# 应用内：顶栏「项目」或 Ctrl+O 换项目（会带新项目重启），「重启」或 Ctrl+Shift+R 快速重启
# 项目选择器的「新建项目…」可选目录、标题、画幅、帧率和时长，建一个空时间线并直接打开

# 或者纯浏览器形态
npm run web

# demo 的素材不进仓库：有参考工程就从里面抽，没有就生成占位图 + 按已提交节拍合成的鼓点
npm run demo

# 命令行走一遍：新建 → 分析节拍 → 自动分镜 → 出帧 → 出片
node cli/vdm.js init projects/myfilm --title "我的片子" --duration 20 --audio bgm.m4a
cd projects/myfilm
node ../../cli/vdm.js import shot01.png shot02.png bgm.m4a
node ../../cli/vdm.js beats --set-duration
node ../../cli/vdm.js plan --style neon --brief $'第一句
第二句'
node ../../cli/vdm.js still 3.2 --out .vdm/frames/a.png
node ../../cli/vdm.js render --from 0 --to 8 --out .vdm/renders/part.mp4
```

Electron 路径可用 `VDM_ELECTRON` 覆盖；Blender 用 `VDM_BLENDER` 覆盖。不设时先找常见安装位置
（`C:/Program Files/Blender Foundation/*`、`/Applications/Blender.app` 等），再在 `PATH` 里找，
所以 Linux / macOS 上装好 `blender`、`electron` 就能直接用。换机器后跑一次 `npm run blender:check`
确认渲染链路。

## 已验证

- `npm test`：100+ 个单元测试全绿（ops / 编辑语义 / 求值 / 场景 / 相机 / 迁移 / 存储锁与监听 / 节拍 / agent 解析）
- Blender 5.0.1（Windows）与 5.2.2（Linux）无头 EEVEE：1080p 单帧约 2–5s（含启动），24s@50% 成片约 70s
- 示例项目 `projects/demo`：24s / 6 分镜 / 13 元素，成片在
  `projects/demo/.vdm/renders/master-*.mp4`（含音轨）
- AI 闭环：在流水线面板选中分镜（或用 CLI）→ 描述改动 → agent 返回 ops → 引擎落盘 → 预览/时间线即时刷新（可撤销）

## 3D 镜头（v0.2）

带相机的项目会把预览切成 **3D 视口**：程序化霓虹城市 + 无人机轨道，实时拖动播放头就是在飞。
成片由 Blender 消费**同一份烘焙包**（城市几何 + 逐帧机位），所以视口里看到的构图就是要渲的。

```bash
cd projects/nightcity
node ../../cli/vdm.js cam ls
node ../../cli/vdm.js cam set fov 72
node ../../cli/vdm.js cam add 7.6 0 34 -40 --look 90,34,-2
node ../../cli/vdm.js world set seed 4242
node ../../cli/vdm.js render --from 0 --to 6 --scale 0.5
```

参数设计见 `docs/SPEC-CAMERA.md`：轨道关键点 / 朝向 / 侧倾 / 抖动 / FOV / 景深 / 运动模糊 +
城市 seed、街区尺寸、楼高分布、亮窗、霓虹、雾。`world.corridor`（默认开、半径 16m）沿航线
清掉镜头会穿过的楼，换 `seed` 也不会撞楼；关掉用 `world set corridor.enabled false`。

相机也能像 3D 元素一样就地展开：相机行默认折叠，点行首 **▾** 打开。`变换` 默认展开，包含
**中心点**（世界坐标）、**位置**（相对中心点的飞行 path）、**画面中心**、**画面位置**、
**透明度**、**缩放**——每行数值跟随播放头，右轨道菱形就是该属性的关键帧，行末 **◆** 打帧 / 删帧。
`镜头 / 构图`（FOV / 看向前方 / 转弯侧倾 / 最大侧倾 / 手动 roll）、`抖动`、`景深 / 模糊` 默认收起，
标题右侧显示摘要，点标题展开。FOV ≥ 180° 自动切等距鱼眼，Blender 这一档走 Cycles。
右侧检查器保留世界参数和渲染按钮。多台相机按时间轴行顺序叠层：非编辑预览里从下到上
alpha-over，越靠上的相机盖住下面的；eye / 右键“单独查看”只影响预览，不影响成片。
编辑视口保留编辑相机单层，退出编辑后看完整相机堆栈。FOV / 看向 / 侧倾 / roll / 抖动 /
景深光圈都能逐帧打点；随机种子、运动模糊开关、快门角是整段设置。展开后东西太多时按
**U**：只展开当前相机/元素里有键的属性，组标题会显示 `▾` 全部 / `▾•` 带键 / `▸` 收起。
Ctrl 点同类元素、属性行或关键帧可加选，选中池始终保持同一种对象。
选中关键帧（菱形）后按 **Delete** / **Backspace** 就把它们一次删掉——相机 path 键、相机参数键、
3D 元素的属性键和 2D 元素键走同一套 ref→op 映射，多个键合成一个 `batch`，撤销一步就全回来。
**时间定位只在顶部标尺**：点/拖标尺才移动播放头；在下方相机/元素/属性行里拖动是**框选关键帧**
（有可见选框，不改变播放头），点空白处清空选中。点击关键帧本身只选中、不跳时间；顶部标尺
也不再画关键帧，相机 path 键只出现在相机的「位置」行，避免多元素时把刻度铺满。
时间轴上的 2D 素材块**右键**有「在播放头切分」（快捷键 **S**），切完自动选中右半；播放头不在
素材范围内或离边缘太近时菜单项置灰并说明原因。
数值框可以直接打字（`0.` 这种半截输入不会被吞掉）；**按住左键左右拖 = 改值、上下拖 = 换挡**：
往下越拖越细、往上越拖越粗（增益 0.0001–10000 单位/像素），换挡本身不动数值，松手按当前档位
吸附到 10 的整数次幂网格（细档可到 0.0001）；**拖出输入框就自动失焦、光标消失**，拖动期间
项目刷新也不会覆盖手上的数值；鼠标悬停时输入框右缘出现 `▴▾`，点一下按步长增减。
透明度一律按百分比显示（0–100%），底层项目里仍是 0..1。

**数值曲线（F2）**：选中同一属性的两个以上关键帧（或者只选中一个元素/物体/相机）按 F2，
时间轴上会盖上一层曲线面板——横轴与时间轴共用同一套缩放和滚动，竖轴是该段的进度；
窗口会按预设自动适配，弹动/周期的过冲不会画出界。右侧预设分三组：基础（线性/缓入/缓出/
缓入缓出）、动力学（弹跳/弹动/周期，随机待做）、图案（步数/弹动步数）。选中预设后直接拖
对应的圆点就能改参数：弹跳拖「步长/回弹」、弹动拖「步长/衰减」和「幅度」、周期拖
「步长/锐度/偏斜/衰减」、步数拖「步长/平滑」、弹动步数拖「步长/幅度」；拖过的曲线显示为
「自定义…」。曲线写在左关键帧的 `curve` 字段上（贝塞尔存 `p1/p2`，参数化预设存 `params`），
清掉就退回原来的 `ease`；Blender 烘焙用同一套公式，JS/Python 对拍见
`tests/fixtures/am-curve-samples.json`。

**相机飞行轨迹**也在 F2 里：选中两个以上路径键（或只选中相机）按 F2，属性下拉里会出现
「飞行轨迹」。**选中的键是分段边界**：每对相邻的选中键是一段，预设分别作用到每一段，
段内未选中的键会被重定时并变暗，边界键保持不动；段与段之间不会互相抢时间。打开面板时
先按真实数据画已经存过的 `curve`+`spanTo`（没有曲线时显示「未应用」），不会凭空造一条
默认曲线；在面板里 Ctrl+点击键可以增删边界，点空白清空选择。点预设才会替换与选区相交的
旧曲线，再按当前分段逐段写入。曲线只改**沿轨迹的速度**，不改变轨迹形状；中间键按
「第一次正向到达」自动重定时（拖动时实时更新），过冲继续走进后面的轨迹、没有后续段就
停在末端，反向过冲在起点夹住。曲线存在每段左端键的 `curve`+`spanTo` 上；清掉后回到原来的
逐段 `ease`/`speed`。视口轨道上的等时小黄点用来直观看出速度快慢。

**时间轴缩放**：底部提示条右侧 `− 100% + 适应`，或 Ctrl+滚轮（以鼠标为锚点）；
双击标尺等于「适应整段」。曲线面板打开时缩放会同步过去，短段放大后再调手柄。

成片也按同一套堆栈合成：每台相机一个 Blender scene，master 用 VSE scene strip 从下到上
alpha-over，画面变换和透明度逐帧写进 strip，所以预览和最终出片走同一份相机数据。
单相机且画面变换为默认值时仍走直接渲染路径，保留项目原有 bloom/grade 合成器。

### 3D 元素

点工具栏 **▦** 打开新建菜单：立方体 / 圆柱 / 钢笔，或 **空元素 / 图片 / 视频 / 3D 文字**。
空元素只做变换和父级，不进成片；图片和视频从 `media/` 里选（先在左侧媒体面板导入）；
3D 文字是带厚度、可进成片的立体文字（顶部的 **T** 仍是 2D 字幕/文字元素）。
新增的图片/视频/文字会出现在编辑视口前方，并选中它，底部出现一条 `元素 · 3D` 行。
选中后可以直接在视口里拖动：拖动会自动在播放头写一个 `pivot`
位置关键帧；选中元素会画出它的运动轨迹，轨迹上的菱形是位置关键帧（播放头所在的那个可以拖）。
点元素行首的 **▾** 就在时间轴里展开它的属性行（内容/变换，中心点/位置/缩放各 3 维），
数值随播放头按关键帧实时同步；已有键时改值=在当前时间写键，没有键时改值=改基础属性；
每行右侧 `◆` 打帧/删帧，右轨道显示该属性的关键帧。元素行的 **⋯** 菜单里有复制/删除/
面向镜头/落地；旋转球、ease 和速度曲线留在右侧检查器。
字段与 ops 细节见 `docs/SPEC-OBJECTS.md`。

**父子集**：选中子元素时，视口里的选中框、轴向手柄和运动轨迹按**世界位置**画；拖动子元素也按
世界位移换算回它自己的本地 `pivot`，不会跳。时间轴里的中心点/位置/缩放仍是**本地值**，带黄色
`本` 徽标；镜头下方会显示父级链和世界坐标。选中父级时子级显示淡轮廓和连线；删除有子级的父级
会弹确认框，可选择“只删父级（当前帧子级保位）”或“父子一起删”。

视口和 Blender 共用同一套求值：没有父级时是 `core/scene.js::objectPose()`，有父级时再叠
`core/hierarchy.js::worldPose()`；`engine/shot.js` 把逐帧世界变换烘进 shot 包，
`blender/vdm_city.py` 按同一组位置/旋转/缩放建盒子。

## 三条设计原则

1. **项目文件是唯一真相源。** `projects/<name>/project.vdm.json` 是纯 JSON，
   UI、CLI、AI 都只通过同一套 `core/ops.js` 操作它；每次保存 rev+1、原子写入、带文件锁。
2. **预览和成片共用一套模型。** `core/evaluate.js` 定义每个元素在任意时刻的状态
   （变换 / 关键帧 / 运动 / 淡入淡出），WebGL 预览和 `blender/vdm_build.py` 各自实现同一套语义。
   预览求快，Blender 求真。
3. **AI 不拥有特权。** agent 用的是和人类一样的 CLI（`vdm set / key set / still / render`），
   每一步都是可见、可回滚的项目变更；它"看图"靠的是引擎给它渲染的片段帧。

## 目录

| 路径 | 作用 |
| --- | --- |
| `core/` | 纯 JS 模型：时间、求值、ops、schema、存储（零依赖，浏览器/Node 共用） |
| `cli/vdm.js` | `vdm` 命令：人用，也**是 AI 的工具面** |
| `engine/` | Node 服务：静态/媒体服务、REST+SSE、Blender 调度、agent 调度、节拍分析 |
| `app/renderer/` | 无构建步骤的 UI（原生 ESM + WebGL2） |
| `app/electron/` | Electron 壳（启动引擎 + 开窗） |
| `blender/` | bpy 场景构建与渲染（图层、文字、合成器、ffmpeg 封装） |
| `projects/` | 项目（示例见 `projects/demo/`） |
| `docs/` | 架构、项目格式、CLI、路线图 |

## 排错 / 日志

所有运行日志（引擎、渲染失败、AI 会话、渲染器异常）都进同一个文件：

```
projects/<name>/.vdm/logs/vdm-YYYY-MM-DD.log     # JSONL：ts/level/msg/meta
```

- 界面：右侧 **日志** 标签页，可按「警告+ / 只看错误」过滤、自动跟随；
- 终端：`npm run logs`（或 `node scripts/logs.mjs --project projects/demo --follow`）；
- 渲染失败会把 Blender 最后几 KB 的 stderr 一并写进日志；
- 渲染器里的 `window.onerror` / `unhandledrejection` 会自动上报，不再只躺在 devtools。
